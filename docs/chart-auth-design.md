# 图表配置角色授权与可见范围 — 设计说明

主对象是**图表配置（CFG-0005）**。可见范围、可视化图表绑定（坐标轴）、图表配置版本均以图表配置主记录为准；数据看板只引用图表，不持有也不替代主记录。

## 1. 数据模型（内存表，见 `backend/app/seed_auth.py`）

| 表 | 职责 |
|---|---|
| `team` / `role` | 团队树与按团队归属的角色（主管/财务/运营/外部评审） |
| `chart_config` | **主记录**：CFG-0005 的坐标轴绑定、数据集、配置版本、范围版本、授权状态 |
| `chart_version` | 版本流水：范围调整与绑定调整分别留痕 |
| `chart_grant` | 逐角色/团队授权：允许维度、editor/viewer、显式拒绝、direct/default、范围版本 |
| `panel_binding` | 看板面板 DASH-0002，仅保存 `引用图表编号` + 授权状态 |
| `filter_binding` | 全局筛选器 FILT-0003，保存联动维度配置 + 授权状态 |
| `review_snapshot` | 只读评审副本：冻结配置版本/范围版本/维度集合 |
| `check_task` | 每次范围变更为相邻模块生成的核对任务，结果回写 |
| `chart_data` | 销售明细，用于演示越权维度在查询入口被拦截 |

## 2. 继承与冲突裁决规则（`services/auth_engine.py`）

1. **团队继承**：角色沿「所属团队 → 父团队 → 根」向上继承**团队默认授权**（`角色编号` 为空的 grant）。
2. **直接授权不跨角色**：带具体角色编号的直接授权只对该角色本人有效，其他角色不会沿父链误继承（主管的 editor 授权不会泄漏给外部评审）。
3. **显式拒绝一票否决**：沿团队链由近及远，命中显式拒绝即终止，拒绝优先于一切允许。
4. **就近原则**：同为允许时，离角色团队最近的一条生效；角色直接授权优先于所在团队的默认授权，默认继承可被就近授权覆盖。
5. **级别**：`editor` 可改绑定与受控维度；`viewer` 只读；团队链无任何授权即无权访问。
6. 每次裁决都返回 `继承来源` 轨迹（团队、授权方式、层级、范围版本），支撑核对清单追溯。

## 3. 可见范围变更的联动（`services/chart_config.py`）

`PUT /api/chart-auth/scope`（仅 editor）：

1. 校验授权合法性（团队/角色存在、级别合法、维度属于数据集、无重复授权）；
2. 旧 grant 整体置「已失效」，新 grant 携带递增后的范围版本（SCOPE-V1→V2…）；
3. 写版本流水；图表主记录授权状态置「待核对」；
4. 为 **DASH-0002 面板**和 **FILT-0003 筛选器**分别生成核对任务，二者状态置「待核对」；
5. 收紧**立即对在线查询生效**（再查被收走的维度直接 403）；
6. 任务逐个回写后，面板/筛选器恢复「已同步」，全部完成后图表恢复「已核对」。

## 4. 越权筛选拦截（`services/chart_query.py`）

- `POST /api/chart-auth/query`：先算有效授权，请求维度不在授权集合内 → **整体 403，不执行聚合**，因此越权筛选不可能改变图表结果（测试验证拒绝前后合法查询行数一致）。
- 筛选器暴露维度 = 筛选器配置联动维度 ∩ 角色授权维度；被隐藏维度随清单返回。

## 5. 发布校验（`POST /api/chart-auth/publish-validate`）

按「角色 × 联动维度 × 数据集」逐角色组合校验：

- 授权维度必须在数据集维度集合内；
- 筛选器实际暴露维度必须是授权维度子集（隐藏维度属预期裁剪，不算越权）；
- 存在未完成核对任务时禁止发布；
- 非 editor 不能发起校验。

## 6. 只读评审副本（`services/review_snapshot.py`）

- 创建瞬间冻结：配置版本、范围版本、可见维度集合、绑定快照，`只读=True`。
- **收紧不回溯**：主管收紧在线范围，旧副本仍保持原范围。
- **放宽不泄漏**：在线新增维度不在冻结集合内，副本访问即 403。
- 任何角色（含主管）对副本的受控维度/绑定修改一律拒绝；非名单角色无法访问。
- 副本不扩大在线权限：评审角色对在线图表仍无授权。

## 7. 三对象授权清单（`GET /api/chart-auth/manifest`）

CFG-0005、DASH-0002、FILT-0003 **分别**列出可见团队、角色裁决与继承来源；面板/筛选器不设独立全局开关，其可见性完全来自图表主记录，杜绝「一个全局开关代替逐对象授权」。

## 8. 验证

`tests/test_chart_auth.py`（服务层直驱，无需额外依赖）覆盖 12 组共 64 项断言：

```bash
cd backend && .venv/bin/python ../tests/test_chart_auth.py
```

涵盖：财务只见地区/运营只见渠道、越权维度 403 且结果不变、范围变更联动核对与状态回写、只读副本冻结与新增维度隔离、显式拒绝优先、就近覆盖、数据集外维度拦截、发布组合校验、越权改绑定拒绝等。

## 9. 接口一览（前缀 `/api/chart-auth`）

| 方法/路径 | 作用 |
|---|---|
| GET `/master` | 主记录三要素 + 版本流水 |
| GET `/manifest` | 三对象授权清单 |
| GET `/decision?role=` | 单角色有效授权裁决与继承来源 |
| PUT `/scope` | 调整可见范围并生成核对任务 |
| GET `/tasks`、POST `/tasks/{id}/complete` | 核对任务查询与回写 |
| POST `/publish-validate` | 发布组合校验 |
| PUT `/binding` | 坐标轴绑定调整（递增配置版本） |
| POST `/query` | 图表查询（越权维度 403） |
| GET `/filter-dimensions?role=` | 筛选器对该角色实际暴露维度 |
| GET `/panels/status` | 看板/筛选器最新授权状态 |
| POST/GET `/review-copies` | 只读副本生成与列表 |
| POST `/review-copies/{id}/attempt-edit` | 验证副本只读不可改 |
